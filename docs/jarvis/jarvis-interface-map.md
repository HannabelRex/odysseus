# Jarvis Interface Map

## Purpose

This document maps existing Odysseus features into a clearer Jarvis user experience while preserving functionality.

## Universal assistant scope

Jarvis remains universal by default.

Primary capabilities:

- chat;
- research;
- coding;
- file and document work;
- notes;
- tasks;
- reminders;
- email;
- calendar;
- memory;
- tools;
- agents;
- automations;
- model management;
- settings and system controls.

Specialist capabilities later:

- SAP ABAP;
- HR portal;
- stock research;
- deployment support;
- business reporting;
- personal finance workflows;
- custom project modes.

## Proposed main navigation

### Home

A new command-center landing page later.

Shows:

- greeting;
- model status;
- safe mode;
- quick actions;
- pending approvals;
- recent missions.

### Chat

The default Mission Console.

### Research

Deep research and source-backed reports.

### Code

Coding mode, model routing to qwen2.5-coder when available.

### Files

Library/documents/files workspace.

### Tasks

Tasks, reminders, follow-ups, and scheduled jobs.

### Calendar

Scheduling and daily planning.

### Email

Communication triage and drafting.

### Memory

Preferences, project memory, skills, and reusable context.

### Tools

Capabilities and permissions.

### Settings

Control Room.

## Right context rail idea

The right rail should be contextual.

For Chat:

- active model;
- active mode;
- memory status;
- available tools;
- approvals.

For Research:

- sources;
- confidence;
- report outline;
- open questions.

For Code:

- project folder;
- model recommendation;
- recent errors;
- safe commands.

For Settings:

- system health;
- local model status;
- backup status.

## User mental model

Jarvis should answer four questions at all times:

1. What am I working on?
2. What intelligence engine is active?
3. What context does Jarvis have?
4. What actions need my approval?
