# Jarvis Chat Mission Console Design

## Core idea

The chat screen becomes the active mission console: a focused workspace where the user can ask, plan, research, code, attach files, and direct Jarvis without feeling buried under raw controls.

## Visual direction

- deep dark command-center background
- glass panels with subtle cyan/violet borders
- clearer message surfaces
- calmer spacing
- premium input area
- contextual right rail on large screens
- compact helper chips for model, safe mode, and capabilities

## Main regions

### 1. Mission surface

The central chat pane should have stronger focus, better max width, and softer panel treatment.

### 2. Composer

The input area should look like a command console, not a plain text box. It should support future additions such as microphone, attachments, slash commands, agent mode, and model switching.

### 3. Context rail

The right rail summarizes what matters:

- current mission
- local model status
- safe mode
- active capabilities
- next recommended actions

The rail is non-destructive and hidden on smaller screens.

### 4. Message readability

Assistant and user responses should have better contrast, spacing, and action affordances. Advanced metadata should remain subtle.

## Feature preservation rule

Existing Odysseus controls remain intact. This phase wraps and improves the experience without removing controls.

## Future enhancements

Later phases can add:

- real mission timeline
- tool call visualization
- approval center integration
- voice controls
- command palette
- mode switching
- richer agent badges
